Overview
MyGo documentation
MyGo builds desktop apps in Go. Each window shows one of two kinds of interface, and one app can have windows of both:
	•	A web page, in the webview of the operating system (WKWebView on macOS, WebKitGTK on Linux, WebView2 on Windows) instead of a bundled browser. The frontend is HTML, CSS and JavaScript built with any tools, and calls your Go code through a TypeScript client that MyGo generates from it, with the types of your Go structs and the documentation of your methods.
	•	Native UI, which MyGo draws itself on the GPU, written in Go alone with package ui: there is no HTML, no JavaScript and no webview to start, so the window opens at once and takes little memory.
Windows of both kinds share the window options and events, the menus and the desktop APIs, and the app is a single Go program of a few megabytes.
A window with a web page, whose frontend calls a Go service:
type Greeter struct{}

// Greet returns a greeting.
func (Greeter) Greet(name string) string { return "Hello, " + name }

func main() {
	mygo.Bind(Greeter{})
	mygo.App.WhenReady(func() {
		mygo.NewWindow(mygo.WindowOptions{Title: "Hello", URL: "/"})
	})
	if err := mygo.App.Run(); err != nil {
		log.Fatal(err)
	}
}
Go
import { Greeter } from "./mygo"; // generated

document.body.textContent = await Greeter.greet("Ada");

A window with native UI, whose view is a Go function of the app's state:
type counter struct{ n int }

func (s *counter) view(c *ui.Context) {
	ui.Column(c).Fill().Center().Gap(12).Children(func() {
		ui.Text(c, fmt.Sprint(s.n)).FontSize(40).Bold()
		if ui.PrimaryButton(c, "Increment").Clicked() {
			s.n++
		}
	})
}

func main() {
	s := &counter{}
	mygo.App.WhenReady(func() {
		mygo.NewWindow(mygo.WindowOptions{
			Title:   "Counter",
			Content: ui.View(s.view),
		})
	})
	if err := mygo.App.Run(); err != nil {
		log.Fatal(err)
	}
}
Go
Web pages suit rich documents, existing web code and what only a browser does; native UI suits tools, settings, inspectors and utilities, and apps that must start instantly.
Getting started
Getting startedInstall the tools, then create, develop and build an app, with native UI or a web frontend.
Building the app
What every app has, whether its windows show native UI or web pages.
	•	Windows: creating and arranging windows of both kinds, their events, and what windows showing web pages do with them: navigation, downloads, permissions, printing.
	•	The application: the lifecycle, quitting, a single instance, deep links, file associations, recent documents, starting at login, well-known directories, the jump list, drawing web pages on Linux, browsing data, cookies and sessions.
	•	Menus and the tray: application, context and Dock menus, keyboard shortcuts and tray icons.
	•	Documents: document-based apps, a window per file, with the File menu, autosave, recovery after a crash, asking to save before closing and quitting, and files changed by other apps.
	•	Languages: the app's messages in the languages it ships, with catalogs of ICU messages, typed Go and TypeScript functions, plural forms, MyGo's own strings, and pseudo locales to test layouts.
	•	Desktop APIs: dialogs, notifications, the clipboard, the shell, displays, dark mode, power, the network status, secrets, watching files and global shortcuts.
	•	Native modules (experimental): Go interfaces implemented in Swift, Kotlin, Rust or Zig, without cgo, for the frameworks and views of macOS, iOS and Android, Rust crates and Zig and C libraries, which the CLI builds, puts into apps and publishes for the users of your Go packages.
	•	Clipboard and drag data: multiple representations, file lists, custom formats, lazy providers, and clipboard persistence.
	•	Audio: sound effects, streamed music and sound an app makes itself, mixed in Go, with WAV, Ogg Vorbis and MP3.
	•	Launchers: apps in the manner of Spotlight and Raycast, summoned by a shortcut over every app, which find and open the apps installed.
Native UI
Native UI has documentation of its own: guides to views, layout, input, navigation and accessibility, and a page for each of its components, from buttons to tables.

Requirements
To develop apps you need Go 1.27 or later and, for the frontend tooling of projects with a web frontend, Bun; projects of native UI need Go alone. MyGo uses no cgo, so there is no C toolchain to install, and any machine can compile the apps of every platform; signing and disk images of macOS apps need a Mac.
